# Review and rebrand

Read by `SKILL.md` after delivery.

## When to offer a review

- The hook line says the strategy was last reviewed more than six months
  ago.
- An event: a major release, a change of target or ambition the user
  mentions, a competitor named who is not in the landscape.

Offer it in one line. If the user says later, run the `touch` command the
hook line gives: it silences the reminder for 30 days.

## The review

1. Send the analyst to redo what is dated, at the depth used in the last
   report (never asked).
2. Re-read the personas against the new research and any interviews, and
   come with what you would change: propose, never interrogate.
3. Review the indicator and the feedback received: one indicator, not a
   dashboard.
4. Check the touchpoints list: places added, places gone.
5. Leave `FOUNDATIONS.md` alone, unless the review shows a rebrand is
   needed.
6. If `STRATEGY.md` or `FOUNDATIONS.md` changed, re-read `VOICE.md` and
   propose the lines to change. Show every change rendered, never as
   Markdown.
7. Set `brand_reviewed` to today.

## Rebrand

On the user's request, or when a review shows the positioning or the
ambition has changed. "It looks old" is not a reason.

- Run the sessions again, from the workshop (`brand_stage: brief`), with
  the current brand as material: the pre-filled brief starts from it.
- **Problem sprint**: list everything that no longer works in the current
  brand, then fix it point by point.
- Repositioning first; everything else follows from it.
- Soft continuity by default: keep what echoes the heritage. A brutal break
  with the brand's core loses the people who knew it.
- If the name changes, go through `references/name.md`.
- Write what is kept and what is dropped from the heritage in
  `docs/brace/brand/DECISIONS.md`.
- End like a first mission: delivery (`references/delivery.md`),
  `brand_stage: done`, `brand_reviewed` set to today.
